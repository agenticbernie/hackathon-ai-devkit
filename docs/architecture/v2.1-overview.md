# HADK v2.1 Architecture

HADK v2.1 is a competition delivery control plane. It stores decisions,
assumptions, blockers, and evidence, then derives the next valid action from
those records.

## Target modules

```text
core
 ├─ workspace
 ├─ competition-intelligence
 ├─ planning
 ├─ agent-bridge
 ├─ verification
 └─ submission
        ↓
       cli
```

`core` owns types, JSON Schema registry metadata, safe path primitives, and
serialization. `workspace` owns confined persistence and migrations.
`competition-intelligence` owns untrusted-source capture and fact review.
`planning` owns strategy, ideas, scope, and architecture contracts.
`agent-bridge` owns canonical packets and adapters for Claude Code, Codex, and
OpenCode. `verification` owns command execution and evidence. `submission`
owns requirement tracking and export.

The dependency graph is acyclic. CLI handlers orchestrate package APIs and do
not implement domain decisions.

## State truth model

Every major artifact has a common metadata envelope:

- `schema_version`
- `created_at`, `updated_at`
- `created_by`
- `source_refs`
- `assumptions`
- `blockers`
- `evidence_refs`
- `verification_status`

Statuses distinguish `planned`, `in_progress`, `blocked`, `unverified`, and
`verified`. Agent reports remain `agent_reported` until a verification contract
or human attestation supplies evidence.

## Evidence truth model

Evidence is append-only and checksummed. It records the source, actor,
timestamp, status, content or confined path, redaction metadata, and evidence
type. Evidence is the only basis for verified build, demo, media, and
submission claims.
